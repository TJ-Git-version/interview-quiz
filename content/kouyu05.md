# 05 · 网络与操作系统（口语版）

> 这块中小厂会问、大厂略过，属于「锦上添花」，不用死磕，能说清关键点即可。

---

## 1. TCP 三次握手？为什么不是两次？

**结论**：SYN → SYN+ACK → ACK，确认双方收发都正常。
**展开**：三次握手能**同时确认双方的发送和接收能力**，还能防止「历史连接」把旧 SYN 当成新连接建起来，浪费资源。两次做不到（只能确认一方），所以是三。
**追问备用**：那为什么不是四次？—— 因为三次足以确认双向，第四次是冗余。

---

## 2. TCP 四次挥手？为什么四次？

**结论**：FIN → ACK → FIN → ACK。
**展开**：TCP 是**半关闭**的，一方发 FIN 只表示「我不再发了」，但对方可能还有数据要发，所以要等对方也发 FIN。所以关闭要分两次（双方各一次），一共四次。

## 3. HTTP 1.1 / 2 / 3 区别？

**结论**：1.1 有队头阻塞，2 多路复用，3 基于 UDP 的 QUIC 更低延迟。
**展开**：HTTP/1.1 长连接、但同一连接有队头阻塞；HTTP/2 用**二进制分帧 + 多路复用**解决了队头阻塞，还有头部压缩；HTTP/3 基于 QUIC（底层 UDP），连接建立更快、支持连接迁移。**对实时性要求高的场景（比如流式）我会考虑这些。**

---

## 4. TCP 和 UDP 区别？

**结论**：TCP 可靠、面向连接；UDP 快、不可靠。
**展开**：TCP 有可靠传输、有序、流量/拥塞控制，适合文件、网页；UDP 无连接、低延迟、可丢包，适合音视频、实时游戏、DNS。**选型看要不要「可靠」和「低延迟」。**

---

## 5. 进程与线程？epoll？

**结论**：进程是资源单位，线程是调度单位；epoll 事件驱动适合高并发。
**展开**：一个进程多个线程共享地址空间，切换成本比进程低。IO 多路复用里，select/poll 是 O(n) 扫描，epoll 是事件驱动 O(1)，所以 Netty、WebFlux 底层用 epoll，能扛大量连接。**这也解释了为什么响应式能少量线程扛高并发。**

---

## 6. 用户态 / 内核态？

**结论**：CPU 两种运行级别，系统调用要切到内核态。
**展开**：用户态权限低，不能直接访问硬件；要操作文件、网络就得系统调用切到内核态。切换有开销，所以避免频繁系统调用。这也是为什么尽量用内存、批量操作、减少锁。
